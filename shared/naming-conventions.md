# Data Modelling Naming Conventions

All objects generated by skills in this library must follow these conventions. Consistency across all generated DDL, YAML, and documentation is required.

---

## General Principles

- Use `snake_case` for all object names (tables, columns, files)
- All names in lowercase
- No abbreviations unless they are universally understood (e.g. `sk`, `bk`, `fk`, `pk`)
- Names should be descriptive enough to be understood without a data dictionary
- Avoid reserved words in all SQL dialects

---

## Dimensional Modelling (Kimball)

### Tables

| Object Type | Pattern | Example |
|---|---|---|
| Fact table | `fct_<entity>_<event>` | `fct_orders_placed`, `fct_sessions_started` |
| Dimension table | `dim_<entity>` | `dim_customer`, `dim_product`, `dim_date` |
| Bridge table | `brd_<fact>_<dimension>` | `brd_orders_promotions` |
| Junk dimension | `dim_<fact>_flags` | `dim_transaction_flags` |
| Aggregate fact | `agg_<entity>_<event>_<grain>` | `agg_sales_daily`, `agg_inventory_monthly` |

### Columns

| Column Role | Pattern | Example |
|---|---|---|
| Surrogate key (PK of dim) | `<table_short>_sk` | `customer_sk`, `product_sk`, `date_sk` |
| Business / natural key | `<entity>_bk` | `customer_bk`, `product_bk` |
| Foreign key in fact | `<dim>_sk` | `customer_sk`, `ship_date_sk` |
| Role-playing FK | `<role>_<dim>_sk` | `order_date_sk`, `ship_date_sk`, `return_date_sk` |
| Degenerate dimension | `<source_key>_ddk` | `order_number_ddk`, `invoice_id_ddk` |
| Measure (additive) | `<noun>_<unit>` | `revenue_usd`, `quantity_units`, `discount_amount_usd` |
| Measure (semi-additive) | `<noun>_<unit>` + comment noting semi-additivity | `account_balance_usd` |
| Effective date (SCD2) | `effective_date` | |
| Expiry date (SCD2) | `expiry_date` | |
| Current row flag (SCD2) | `is_current` | BOOLEAN, `TRUE` for active row |
| Current attribute (SCD6) | `current_<attr>` | `current_region`, `current_segment` |
| Previous attribute (SCD3) | `previous_<attr>` | `previous_region` |

## Snowflake Schema (sub-dimensions)

Sub-dimensions follow the same `dim_` prefix pattern and use the specific hierarchy level name:

| Level | Pattern | Example |
|---|---|---|
| Leaf level | `dim_<entity>` | `dim_product` |
| Parent level | `dim_<parent_entity>` | `dim_subcategory` |
| Grandparent | `dim_<grandparent_entity>` | `dim_category` |
| Root | `dim_<root_entity>` | `dim_department` |

The FK chain is always named `<parent>_sk` in the child table.

## dbt Layer Naming

### Model Files

| Layer | Pattern | Example |
|---|---|---|
| Staging | `stg_<source>__<entity>.sql` | `stg_salesforce__accounts.sql` |
| Intermediate | `int_<entity>_<transformation>.sql` | `int_orders_with_customer.sql` |
| Mart – Fact | `fct_<entity>_<event>.sql` | `fct_orders_placed.sql` |
| Mart – Dimension | `dim_<entity>.sql` | `dim_customer.sql` |

Note: double underscore `__` separates source from entity in staging; single `_` everywhere else.

### YAML Files

| File | Purpose |
|---|---|
| `sources.yml` | Declares raw source tables |
| `schema.yml` | Documents and tests all models (one per directory, or one per model) |
| `_sources.yml` | Alternative convention for source-specific schemas |

### dbt Snapshot Files

| Pattern | Example |
|---|---|
| `<entity>_snapshot.sql` | `customer_snapshot.sql` |

## Data Vault 2.0

### Tables

| Object Type | Pattern | Example |
|---|---|---|
| Hub | `hub_<entity>` | `hub_customer`, `hub_product`, `hub_order` |
| Link | `lnk_<entity1>_<entity2>` | `lnk_order_customer`, `lnk_order_product` |
| Satellite (Hub) | `sat_<entity>_<source>` | `sat_customer_crm`, `sat_product_erp` |
| Satellite (Link) | `sat_<entity1>_<entity2>_<source>` | `sat_order_product_pos` |
| Reference Table | `ref_<entity>` | `ref_country`, `ref_currency` |
| Point-In-Time | `pit_<entity>` | `pit_customer` |
| Bridge | `brd_<entity>` | `brd_customer_hierarchy` |

### Columns

| Column Role | Pattern | Example |
|---|---|---|
| Hub hash key (PK) | `<entity>_hk` | `customer_hk`, `product_hk` |
| Link hash key (PK) | `lnk_<e1>_<e2>_hk` | `lnk_order_customer_hk` |
| Business key | `<entity>_bk` | `customer_bk`, `product_bk` |
| Load date | `load_date` | TIMESTAMP, populated with ETL load time |
| Load end date | `load_end_date` | TIMESTAMP, NULL for current record |
| Record source | `record_source` | VARCHAR, source system identifier |
| Hash diff | `hash_diff` | CHAR(32) or CHAR(64), hash of all descriptive cols |

## General Column Conventions

| Category | Convention | Example |
|---|---|---|
| Date columns | `<context>_date` | `order_date`, `birth_date`, `effective_date` |
| Timestamp columns | `<context>_at` or `<context>_timestamp` | `created_at`, `updated_at`, `loaded_at` |
| Boolean flags | `is_<condition>` | `is_current`, `is_deleted`, `is_active` |
| Count measures | `<noun>_count` | `line_item_count`, `session_count` |
| Amount measures | `<noun>_amount` | `discount_amount`, `tax_amount` |
| Quantity measures | `<noun>_quantity` | `units_quantity` |
| ID columns | `<entity>_id` (source system) or `<entity>_sk` (warehouse) | `customer_id`, `customer_sk` |
| Audit columns | `_created_at`, `_updated_at`, `_loaded_at` | Prefixed with `_` to sort last |

## File and Directory Naming

| Object | Convention |
|---|---|
| Skill files | `SKILL.md` (uppercase, in skill subdirectory) |
| Example files | `requirements.md`, `<skill>-output.md` |
| Shared reference files | `glossary.md`, `naming-conventions.md`, `sql-dialect-guide.md` |
| SQL migration files | `YYYYMMDD_<description>.sql` |
